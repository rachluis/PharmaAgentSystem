# 摘要

在当前全球医药行业“医药分开”与合规监管日益趋严的背景下，传统制药企业的营销模式正面临从粗放式向精细化转型的巨大挑战。传统的客户关系管理（CRM）系统往往局限于基础数据的记录与简单统计，缺乏对医生行为特征的深度挖掘，且市场策略的制定高度依赖人工经验，难以在海量数据中快速精准地定位高价值客户并生成个性化营销方案。针对上述痛点，本文设计并实现了一套《基于多智能体协作的医药市场画像与策略生成系统》。

本系统提出了一种将传统机器学习算法与大语言模型（LLM）智能体深度融合的技术架构。首先，基于美国 CMS Open Payments 公开数据集，通过 ETL 流程清洗并整合了 1,540 万条原始支付记录，构建了包含 738,773 名医生的多维特征数据库。其次，引入 RFM（Recency, Frequency, Monetary）客户价值模型，并通过 K-Means 聚类算法将医生群体划分为“核心高价值”、“潜力成长”与“低活跃”三类典型特征群体。针对聚类结果中的长尾分布问题（平均金额 $3,378 与中位数 $174 的巨大差异），本文采用了对数变换与标准化处理以提升模型鲁棒性。最后，利用 Dify 平台构建了基于大语言模型的智能体工作流，该智能体能够根据聚类中心的统计特征（如 Cluster 0 的平均互动频次 43.84 次），自动化生成包含学术推广建议、合规风险提示及个性化拜访计划的完整市场策略报告。

系统测试结果表明，该系统能够有效处理千万级规模的医疗交易数据，聚类分析响应时间控制在 60 秒以内。实验数据显示，系统成功识别出占比 31.1% 的核心高价值医生群体，该群体贡献了绝大部分的市场份额。通过 AI 智能体生成的策略报告在逻辑性、针对性与合规性方面均达到了辅助决策的标准，显著提升了医药市场分析的效率与科学性。本文的研究不仅验证了“判别式 AI + 生成式 AI”在垂直领域应用的可行性，也为医药企业的数字化转型提供了具有实践价值的解决方案。

**关键词**：医药数据挖掘；客户细分；K-Means 聚类；大语言模型；智能体；RFM 模型

# 第1章 绪论

## 1.1 研究背景

### 1.1.1 全球医药行业的合规与转型压力

随着全球范围内医疗反腐力度的加大以及“医药分开”政策的深入实施，制药企业的市场环境发生了根本性变化。在中国，国家卫健委等部门联合开展的医疗领域腐败问题集中整治工作，使得传统的“带金销售”、不合规的学术赞助等行为受到严厉打击。在美国，自 2013 年起实施的《医生薪酬阳光法案》（Physician Payments Sunshine Act）强制要求制药企业公开对医生和教学医院的支付信息（即 CMS Open Payments 数据），旨在通过透明化手段遏制利益输送。这一大背景迫使药企必须摒弃过去单纯依靠财务激励的营销手段，转向以学术价值为导向、合规透明的精细化营销模式。

### 1.1.2 传统 CRM 的局限性与数据驱动的迫切性

在数字化转型的浪潮中，尽管大多数药企已部署了 CRM 系统，但现有的系统多扮演着“电子记录本”的角色，主要用于记录拜访时间、地点等基础信息。面对千万级的交易流水与数十万计的医生档案，传统系统存在显著的短板：

1. **缺乏深度洞察**：难以从海量的交易频次、金额及时间间隔中提取出能够反映医生学术偏好与忠诚度的深层特征。
2. **决策滞后**：市场策略的制定往往滞后于市场变化，且高度依赖区域经理的个人经验，缺乏客观数据的支撑。
3. **个性化缺失**：难以针对不同价值层级的医生群体（如学术领袖 vs 社区医生）制定差异化的服务方案。
因此，如何利用大数据技术挖掘沉淀数据的价值，并借助人工智能技术实现自动化的策略辅助，成为药企提升核心竞争力的关键。

## 1.2 研究意义

### 1.2.1 理论意义

本文探索了判别式人工智能（Discriminative AI）与生成式人工智能（Generative AI）在垂直行业中的融合应用模式。具体而言，将擅长处理结构化数据、发现客观规律的 K-Means 聚类算法（判别式），与擅长逻辑推理、文本生成的 Large Language Model（生成式）相结合。这种“理性数据分析 + 感性策略生成”的协作机制，为从数据挖掘到辅助决策的完整链路提供了新的理论视角，丰富了多智能体协作系统（Multi-Agent System）在管理信息系统领域的应用案例。

### 1.2.2 实践意义

从应用层面来看，本文设计的系统具有显著的商业价值与社会效益：

1. **降本增效**：通过自动化的 ETL 与聚类分析，将原本需要数周的人工市场分析周期缩短至分钟级，大幅降低了人力成本。
2. **科学决策**：基于 73 万名医生的全量数据而非抽样数据进行画像，避免了“幸存者偏差”，确保了市场策略的客观性与准确性。
3. **合规经营**：系统内置的 AI 策略生成模块将合规性作为 Prompt 的核心约束，有助于药企在红线范围内开展高效的学术推广活动。

## 1.3 国内外研究现状

### 1.3.1 医药市场细分与 RFM 模型应用

在市场营销领域，RFM（Recency, Frequency, Monetary）模型是衡量客户价值的经典工具。国外的研究较早将 RFM 应用于医疗卫生领域，例如著名的梅奥诊所曾利用患者的就诊频率与费用模型优化医疗资源配置。在国内，近年来也有学者尝试利用机器学习算法对医院的药品流向数据进行分析。然而，现有研究多集中于医院端的药品库存管理或患者端的疾病预测，专门针对“药企-医生”这一 B2B2C 特殊关系的营销画像研究相对较少，且大多停留在统计描述层面，缺乏对聚类结果的深度应用。

### 1.3.2 客户关系管理（CRM）系统的演进

CRM 系统经历了从操作型（记录数据）、分析型（BI 报表）到智能型（AI 预测）的演进。早期的医药 CRM 主要解决销售代表的打卡与费用报销问题。随着大数据技术的发展，以 Salesforce、Veeva 为代表的行业巨头开始集成 predictive analytics（预测性分析）功能。但在实际落地中，这些通用型 SaaS 软件往往难以适配特定数据集（如 CMS Open Payments）的复杂结构，且昂贵的订阅费用限制了其在中小型药企中的普及。

### 1.3.3 生成式 AI 在营销领域的应用

自 ChatGPT 发布以来，生成式 AI 在内容营销、客户服务等领域的应用呈爆发式增长。目前，利用 LLM 生成营销文案、邮件话术已较为成熟。但在医药领域，由于其高度的专业性与严苛的合规要求，直接使用通用大模型生成市场策略往往会出现“幻觉”或不合规建议。如何通过 Prompt Engineering（提示工程）与 RAG（检索增强生成）技术，让大模型读懂专业的业务报表并生成可信的决策建议，是当前学术界与产业界关注的热点。

## 1.4 本文主要工作

本文旨在设计并实现一个集数据处理、特征挖掘与策略生成于一体的智能医药市场分析系统。主要工作内容如下：

### 1.4.1 数据清洗与 ETL 流程构建

针对 CMS Open Payments 原始数据集数据量大（1540 万条）、噪声多、字段复杂的特点，设计了完整的 ETL（Extract, Transform, Load）流水线。通过 Python 脚本完成了数据的去重、缺失值填充及异常值处理，并将非结构化的交易流水聚合为以 NPI（国家医生编号）为唯一标识的医生画像表，清洗后的有效医生数据达 738,773 条，为后续分析奠定了高质量的数据基础。

### 1.4.2 基于 RFM 模型与 K-Means 的客户分群

构建了适配医药场景的 RFM 模型，定义 Recency 为最近一次学术交流距今的时间，Frequency 为年度互动频次，Monetary 为年度涉及的经费总额。针对数据分布的极度右偏现象（长尾特征），创新性地在聚类前引入了 Log-transformation（对数变换）预处理。通过肘部法则（Elbow Method）确定了最优聚类数 K=3，并成功识别出高频高价值的“核心专家”、低频高潜力的“成长客户”以及长尾的“普通客户”，通过轮廓系数（Silhouette Score）验证了聚类的有效性。

### 1.4.3 基于 Dify 的智能体工作流编排

利用 Dify 中间件平台，编排了“分析师-策划师”协作的智能体工作流。系统后端负责将 K-Means 计算出的聚类中心统计数据（如各类别的平均金额、占比、主导专业）标准化为 JSON 格式的 Context，即时注入到 LLM 的提示词中。设计了包含角色设定、任务约束、输出格式控制的 System Prompt，使得 AI 能够扮演资深医药市场顾问，输出包含数据解读、SWOT 分析及行动建议的结构化 Markdown 报告。

### 1.4.4 全栈系统实现与可视化

采用前后端分离架构完成了系统开发。后端使用 FastAPI 框架构建了高性能的 RESTful API，集成了 Scikit-learn 算法库与 SQLite 数据库；前端基于 Vue 3 框架与 ECharts 组件库，实现了聚类结果的 3D 散点图可视化、雷达图特征对比及动态交互分析面板。系统经测试，在处理数十万级数据请求时保持了良好的响应性能与稳定性。

## 1.5 论文结构安排

本文共分为六章，具体安排如下：

* **第一章 绪论**：阐述研究背景与意义，综述国内外相关现状，概括本文核心工作与章节安排。
* **第二章 相关技术与理论**：介绍 RFM 模型、K-Means 算法原理、大语言模型 Agent 技术及系统开发所用的技术栈。
* **第三章 系统需求分析与设计**：详细分析系统功能与非功能需求，设计系统总体架构、数据库模型及 Agent 工作流。
* **第四章 关键模块实现**：详细论述 ETL 数据处理、聚类算法服务化封装、Dify API 对接及前端可视化的代码实现。
* **第五章 数据分析与系统测试**：展示数据清洗结果，对比不同 K 值的聚类效果，分析生成的市场策略报告质量，并进行系统性能测试。
* **第六章 总结与展望**：总结全文工作成果，指出系统存在的局限性，并对未来的优化方向进行展望。
